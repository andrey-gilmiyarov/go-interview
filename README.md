# Go и backend — локальный справочник

Это локальный справочник по Go `1.27.1` и backend-разработке: 42 Go-статьи в восьми разделах, 20 Go-заданий, восемь глав Kafka, восемь глав PostgreSQL, проверяемые исходники, пять интерактивных моделей и карты дополнительных материалов. Условие и ответ остаются в репозитории; сайт не запускает пользовательский код, не хранит прогресс и не требует учётной записи.

## Ежедневное чтение

Нужен Node.js `22.22.2`; версия закреплена в файле `.node-version`. При первой настройке установите зависимости из lockfile, соберите статический сайт и откройте его локальный просмотр:

```sh
npm ci
npm run docs:build
npm run docs:serve
```

Статический просмотр доступен по адресу http://127.0.0.1:4173. Он использует результат последней сборки; после правок повторите `npm run docs:build` и перезапустите `npm run docs:serve`.

## Редактирование справочника

Для работы над статьями запустите авторский сервер:

```sh
npm run docs:dev
```

Адрес по умолчанию — http://127.0.0.1:5173. Изменения prose-файлов обновляются через HMR. После добавления темы или изменения реестров навигации и метаданных остановите и заново запустите `npm run docs:dev`, чтобы перечитать JSON-реестры.

## Практика в IDE

Код пишется локально в IDE с Go `1.27.1`. Откройте условие на сайте или в `practice/<id>/README.md` и выполните задание в `practice/<id>/starter/starter.go`. Пока ответ не реализован, проверка с тегом exercise ожидаемо показывает незавершённые проверки:

```sh
go test -tags=exercise ./practice/<id>/starter
```

Проверенное решение и объяснение доступны отдельно. Запустите тесты эталонного варианта так:

```sh
go test ./practice/<id>/solution
```

Код общих примеров проверяется командой `go test ./examples/...`. Браузер не отправляет код на сервер и не проверяет задание автоматически. Условия и разборы подключаются из канонических файлов `practice/<id>/README.md` и `practice/<id>/SOLUTION.md`; страницы решений исключены из локального поиска.

## Полная проверка

Перед интеграцией выполните проверки сайта и Go-пакетов:

```sh
npm run test:site
npm run docs:check
npm run docs:build
go test ./...
go test -race ./...
go build ./...
go vet ./...
```

Полный `docs:check` требует все 42 темы и 20 упражнений, валидирует взаимные ссылки реестров, структуру практики и локальные ссылки. Точные результаты текущей проверки записаны в [docs/reports/verification.md](docs/reports/verification.md).

## Версии и зависимости

Go-код рассчитан на toolchain `1.27.1`; модуль использует стандартную библиотеку и единственную прямую Go-зависимость `golang.org/x/sync v0.22.0`. Для сайта закреплены Node.js `22.22.2`, VitePress `1.6.4` и Vue `3.5.43`. Для основных Go-примеров контейнеры и базы данных не нужны. Kafka и PostgreSQL имеют отдельные опциональные лаборатории со своими Go-модулями и Docker Compose.

Известное ограничение инструментария: при проверке lockfile npm audit сообщил о трёх транзитивных advisories в одобренном дереве VitePress 1.6.4: двух moderate и одном high; наиболее высокий относится к Windows, совместимого исправления аудит не предложил. Версия VitePress и зависимости не обновлялись в рамках этой миграции.

## PostgreSQL

[Учебный маршрут](site/postgres/index.md) объясняет механизмы PostgreSQL и Senior-задачи без повторения базового SQL. [Лаборатория](labs/postgres/README.md) использует PostgreSQL 17.11, Go 1.27.1 и pgx v5.11.0.

```sh
cd labs/postgres
./lab.sh up
./lab.sh run isolation
./verify.sh
./lab.sh down
```

Корневой `go test ./...` не проверяет вложенные модули: лаборатория проверяется отдельно. Полный content checker проверяет также восемь PostgreSQL-глав. [Отчёт проверки](docs/reports/postgresql-verification.md).
