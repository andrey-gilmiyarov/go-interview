# Разбор: Что увидят две транзакции

## Механизм и решение

Обе RR-транзакции видят сумму 2, обновляют разные строки и могут завершиться: сумма становится 0. Serializable обнаруживает опасные зависимости; одна сторона откатывается. Повтор всей транзакции видит сумму 1 и отказывается убирать последний товар. Для RC отдельный SELECT получает новый snapshot; это не делает предыдущее решение атомарным.

## Проверка

```sh
./lab.sh run isolation
```

Успех означает проверку инвариантов, а не совпадение времени или номера транзакции. При ошибке сначала определите фазу и SQLSTATE; не убирайте assertion ради зелёного результата.

## Senior-усложнение

Общая строка-guard или блокировка обеих строк также могут защитить инвариант. Цена — сериализация доступа. Нельзя исправить retry, повторив только прежний UPDATE без повторной проверки суммы.
