# Почему VACUUM не очищает версии

## Условие

Долгая транзакция прочитала таблицу. Другая сессия обновила все строки. DBA выполнил VACUUM, но видит версии, которые пока нельзя убрать.

Предскажите видимость в старом snapshot и возможности двух запусков VACUUM: до и после COMMIT читателя. Назовите диагностические поля и объясните, почему размер файла не критерий.

## Работа

Из каталога лаборатории после `./lab.sh up`:

```sh
./lab.sh run long-transaction
```

Для ручного воспроизведения используйте `schedule.sql` в каталоге задачи: выполняйте отмеченные шаги в отдельных psql-сессиях. Это расписание, а не файл для запуска целиком.

<details><summary>Подсказка</summary>

Убедитесь, что reader действительно удерживает snapshot. Одного BEGIN недостаточно для нужного эксперимента.

</details>
