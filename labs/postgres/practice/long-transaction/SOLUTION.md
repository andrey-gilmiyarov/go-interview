# Разбор: Почему VACUUM не очищает версии

## Механизм и решение

Repeatable Read после первого SELECT сохраняет старые значения. backend_xmin показывает удерживаемый горизонт. VACUUM VERBOSE до commit сообщает версии, ещё необходимые читателю; после commit их можно удалить. Новое чтение видит обновлённую сумму. Проверять освобождение места внутри таблицы и уменьшение файла — разные задачи.

## Проверка

```sh
./lab.sh run long-transaction
```

Успех означает проверку инвариантов, а не совпадение времени или номера транзакции. При ошибке сначала определите фазу и SQLSTATE; не убирайте assertion ради зелёного результата.

## Senior-усложнение

Не делайте автоматический вывод только по оценке n_dead_tup. Учитывайте slots, другие snapshots, autovacuum и скорость записи. Лаборатория отключает autovacuum только для этой временной учебной таблицы, чтобы не смешивать наблюдения.
