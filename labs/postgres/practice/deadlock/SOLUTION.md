# Разбор: Найти цикл ожидания

## Механизм и решение

Рёбра A→B и B→A образуют цикл. Детектор прерывает одну транзакцию с 40P01; жертва не часть бизнес-контракта. После rollback другая сторона продолжает. Единый порядок 1→2 устраняет этот цикл. Сценарий сначала наблюдает первое ожидание через pg_blocking_pids, затем создаёт второе ребро.

## Проверка

```sh
./lab.sh run deadlock
```

Успех означает проверку инвариантов, а не совпадение времени или номера транзакции. При ошибке сначала определите фазу и SQLSTATE; не убирайте assertion ради зелёного результата.

## Senior-усложнение

Retry должен быть ограничен и охватывать всю транзакцию. lock_timeout ограничит ожидание, но не устранит причину. При добавлении новых ресурсов пересмотрите глобальный порядок.
