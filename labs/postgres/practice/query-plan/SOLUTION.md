# Разбор: Защитить выбор индекса

## Механизм и решение

B-tree(customer_id,created_at DESC) INCLUDE(id) соответствует равенству и порядку. При достаточной селективности можно остановиться после LIMIT, не сортируя всю таблицу. Проверять нужно actual rows, loops, buffers, сортировку и одинаковый результат. Seq Scan может быть рационален; тест не фиксирует единственный узел или миллисекунды.

## Проверка

```sh
./lab.sh run query-plan
```

Успех означает проверку инвариантов, а не совпадение времени или номера транзакции. При ошибке сначала определите фазу и SQLSTATE; не убирайте assertion ради зелёного результата.

## Senior-усложнение

Для keyset pagination нужен устойчивый порядок с id при одинаковом времени. Partial index подходит только при доказуемом predicate. Производительность на одном клиенте не доказывает полезность индекса для всех запросов.
