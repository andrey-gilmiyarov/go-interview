# Защитить выбор индекса

## Условие

Список последних заказов клиента медленно строится на 100000 строк. Есть PK(id), но запрос фильтрует customer_id и сортирует created_at.

Сначала объясните ожидаемую работу. Выполните эксперимент, прочитайте оба JSON-плана и предложите индекс. Назовите цену для INSERT и то, как изменится решение при сильном перекосе клиентов.

## Работа

Из каталога лаборатории после `./lab.sh up`:

```sh
./lab.sh run query-plan
```

Для ручного воспроизведения используйте `schedule.sql` в каталоге задачи: выполняйте отмеченные шаги в отдельных psql-сессиях. Это расписание, а не файл для запуска целиком.

<details><summary>Подсказка</summary>

Индекс должен помогать и фильтрации, и порядку. Наличие поля в INCLUDE не означает нулевые Heap Fetches.

</details>
