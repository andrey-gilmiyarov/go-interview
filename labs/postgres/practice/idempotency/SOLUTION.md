# Разбор: Повторное создание заказа

## Механизм и решение

UNIQUE(request_key) выбирает победителя. ON CONFLICT DO NOTHING RETURNING id либо создаёт заказ, либо не возвращает строку. В последнем случае отдельный SELECT в RC видит завершившегося конкурента и сравнивает все поля запроса. У победителя списание и INSERT принадлежат одному tx. Неподтверждённый commit восстанавливается по тому же ключу.

## Проверка

```sh
./lab.sh run idempotency
go test -tags=exercise ./practice/idempotency/starter
go test -tags=integration ./practice/idempotency/solution
```

Успех означает проверку инвариантов, а не совпадение времени или номера транзакции. При ошибке сначала определите фазу и SQLSTATE; не убирайте assertion ради зелёного результата.

## Senior-усложнение

DO UPDATE может дать RETURNING сразу, но бессмысленное обновление создаёт стоимость и может запускать триггеры. Условие задачи не допускает удаления ключей во время запросов; retention и повтор через месяц требуют нового контракта.
