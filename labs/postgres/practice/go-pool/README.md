# Соединения после ошибок

## Условие

Пул ограничен одним соединением. После ошибки чтения следующий запрос неожиданно ждёт. Обработчик использует request context, который уже отменён.

Реализуйте ReadStocks(ctx,pool): прочитайте остатки в транзакции, верните ошибки итерации, завершите tx на любом пути. После отмены и ошибки SQL пул должен оставаться пригодным к работе.

## Работа

Из каталога лаборатории после `./lab.sh up`:

```sh
./lab.sh run go-pool
go test -tags=exercise ./practice/go-pool/starter
go test -tags=integration ./practice/go-pool/solution
```

Откройте starter в IDE. Не меняйте контракт функции и общие проверки. Условие использует схему сценария, подготовленную тестом; не запускайте несколько проверок этого ID одновременно.

<details><summary>Подсказка</summary>

Проверьте rows.Close, rows.Err и context для rollback. Отличайте Begin на pool от автоматического управления жизнью tx.
