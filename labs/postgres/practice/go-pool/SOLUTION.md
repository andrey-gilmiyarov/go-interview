# Разбор: Соединения после ошибок

## Механизм и решение

Сразу после Begin устанавливается defer rollback с отдельным bounded context. Query rows закрывается, после итерации проверяется Err. До commit rows уже исчерпаны. Отмена request context не заменяет явного завершения pgx tx; при сетевой ошибке connection может быть уничтожен и заменён пулом.

## Проверка

```sh
./lab.sh run go-pool
go test -tags=exercise ./practice/go-pool/starter
go test -tags=integration ./practice/go-pool/solution
```

Успех означает проверку инвариантов, а не совпадение времени или номера транзакции. При ошибке сначала определите фазу и SQLSTATE; не убирайте assertion ради зелёного результата.

## Senior-усложнение

После неопределённого COMMIT нельзя универсально повторять функцию. Размер pool не исправляет утечку. В тесте проверяется новое успешное подключение, а не сохранение того же физического соединения.
