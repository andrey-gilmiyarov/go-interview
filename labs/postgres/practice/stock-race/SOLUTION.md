# Разбор: Последний товар

## Механизм и решение

Условный UPDATE меняет строку только при достаточном остатке. В Read Committed конкурентный UPDATE после ожидания повторно проверяет условие на обновлённой версии. RowsAffected=0 переводится в ErrStock. INSERT заказа выполняется через тот же tx; deferred rollback сохраняет остаток при ошибке INSERT. Успешный commit — единственная точка подтверждения.

## Проверка

```sh
./lab.sh run stock-race
go test -tags=exercise ./practice/stock-race/starter
go test -tags=integration ./practice/stock-race/solution
```

Успех означает проверку инвариантов, а не совпадение времени или номера транзакции. При ошибке сначала определите фазу и SQLSTATE; не убирайте assertion ради зелёного результата.

## Senior-усложнение

FOR UPDATE полезен при многошаговом решении, но требует удерживать строку до конца транзакции. Для нескольких товаров захватывайте строки в едином порядке. CHECK(stock>=0) не доказывает равенство продаж фактическому списанию.
