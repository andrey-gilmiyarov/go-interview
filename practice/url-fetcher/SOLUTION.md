# Разбор: url-fetcher

Workers обрабатывают индексы, поэтому массив результатов сохраняет порядок. Для каждого URL создаётся собственный дочерний контекст с deadline. Ошибка создания запроса, транспорта или закрытия body остаётся в соответствующем Result; HTTP status сам по себе не превращается в ошибку.

При отмене родителя producer прекращает выдавать задания, HTTP-запросы получают отмену, а функция ждёт worker-ы перед возвратом <code>nil, ctx.Err()</code>. Это предполагает, что используемый HTTP transport соблюдает контекст. Повторно использовать один timeout на worker нельзя: время ожидания предыдущего URL тогда влияло бы на следующий.
