# Структурное логирование через log/slog

## Коротко

`log/slog` отделяет вызов логирования от формата и назначения записи. `Logger` передаёт структурированный `Record` обработчику `Handler`, который решает уровень фильтрации, формат, группы и вывод. Добавляйте стабильные поля с типизированными атрибутами, не включайте секреты и персональные данные по умолчанию, а выбор JSON или текстового вывода делайте конфигурацией приложения.

## Как работает

`slog.NewTextHandler` и `slog.NewJSONHandler` пишут в `io.Writer`; `HandlerOptions.Level` задаёт минимальный уровень, а `AddSource` просит включить место вызова. До форматирования logger может спросить `Handler.Enabled`, чтобы не строить запись ниже порога, но аргументы вызова уже вычислены языком Go. `LogAttrs` сокращает конвертацию пар ключ-значение; чтобы не выполнять дорогое форматирование поля на отключённом уровне, сначала явно вызовите `logger.Enabled(ctx, level)`, а затем сформируйте Attr. `Logger.With` добавляет постоянные поля, например имя сервиса или версию, а `WithGroup` группирует последующие атрибуты. Это помогает собирать логи разных пакетов в согласованную схему.

Методы `Info`, `Warn` и `Error` удобны для обычного сообщения и пар аргументированных полей; `slog.String`, `slog.Int`, `slog.Duration`, `slog.Bool` и `slog.Group` явно задают тип. `slog.Any` оставляет больше работы handler и может передать объект с чувствительными или нестабильными полями. Не считайте JSON-handler схемой продукта автоматически: имя ключей, группы, кодирование времени и правила редактирования всё равно часть выбранной конфигурации.

`Handler` может вызываться конкурентно. Собственная реализация должна синхронизировать изменяемое состояние и корректно возвращать новые handlers из `WithAttrs` и `WithGroup`. Контекст передаётся для доступа к значениям, но отмена контекста не должна прерывать запись лога: события об отмене запроса часто нужны именно для диагностики отмены. Значения context не становятся полями автоматически; извлекайте только утверждённые поля и не помещайте в контекст секреты для последующего массового логирования.

Добавление caller source может быть полезно для локальной диагностики, но имеет цену вычисления и раскрывает пути исходного дерева. Логируйте причину и контекст отказа, а не полный объект запроса, токен авторизации, пароль, cookie, тело или произвольное значение пользователя. Для корреляции используйте ограниченный идентификатор операции; высококардинальные значения не должны бездумно становиться метками метрик. Стандартный пакет не заменяет политику ротации файлов, отправки, семплирования или хранения.

## Пример

Обработчик пишет JSON в переданный writer. Группа помещает поля запроса под одним ключом, а стабильное имя сервиса остаётся общим полем. Пример логирует статус и длительность, но не заголовки авторизации или тело:

```go
package main

import (
	"bytes"
	"context"
	"fmt"
	"log/slog"
	"time"
)

func main() {
	var output bytes.Buffer
	handler := slog.NewJSONHandler(&output, &slog.HandlerOptions{
		Level:     slog.LevelInfo,
		AddSource: false,
	})
	logger := slog.New(handler).
		With(slog.String("service", "catalog")).
		WithGroup("request")

	logger.LogAttrs(context.Background(), slog.LevelInfo, "completed",
		slog.String("method", "GET"),
		slog.Int("status", 200),
		slog.Duration("elapsed", 12*time.Millisecond),
	)
	fmt.Print(output.String())
}
```

Отдельный writer позволяет внедрить stdout, тестовый буфер или другой назначенный sink. Handler сам не закрывает writer: жизненный цикл sink принадлежит приложению. `LogAttrs` позволяет передать заранее типизированные значения. Если уровень ниже порога, logger не передаст запись handler для форматирования, хотя аргументы самого вызова уже вычислены.

## Ошибки и ограничения

- Не передавайте весь запрос через `slog.Any`: сериализация может раскрыть секреты и нестабильные детали.
- Не считайте уровень фильтрации заменой безопасной обработки данных: сообщение выше порога всё ещё может содержать пароль.
- Не предполагайте, что `context.Context` автоматически добавит trace-id или отменит handler.
- Не добавляйте caller source и высококардинальные атрибуты без оценки затрат, приватности и объёма хранения.
- Не реализуйте `Handler` с общей map или буфером без защиты от параллельных вызовов.
- Не игнорируйте вывод и ошибки инфраструктуры: методы Logger не возвращают ошибки `Handle` вызывающему коду.

При диагностике проверьте установленный handler, минимальный уровень, writer и то, вызывается ли поле до или после фильтра. Тестируйте записи через буфер или специализированный тестовый handler: проверяйте ключевые поля и уровни, а не полное форматирование, если пробелы и порядок ключей не входят в контракт.

## Практика

Опишите для одного HTTP-запроса набор безопасных полей, один уровень для каждого исхода и формат для локальной разработки и production. Проверьте через buffer handler, что ошибка содержит идентификатор операции и класс причины, но не токен и не полное тело. Отдельно укажите, кто владеет writer и политикой доставки.
