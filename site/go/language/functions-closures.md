# Функции и замыкания

## Коротко

Функция в Go имеет сигнатуру с типами параметров и результатов. Значение функционального типа можно сохранить в переменную, передать как callback или вернуть из другой функции. Нулевое значение функционального типа равно `nil`; попытка вызвать такую переменную приводит к panic. Функциональный литерал может обращаться к переменным из окружающей области видимости — это замыкание.

Замыкание сохраняет доступ к переменной, а не снимок её текущего значения. Несколько замыканий могут разделять одну переменную. Это удобно для состояния с явным сроком жизни, но требует внимания к циклам, повторным запросам и конкурентному доступу.

## Как работает

Функциональный литерал записывает поведение рядом с местом, где оно нужно: сортировщик получает функцию сравнения, обработчик — middleware, функция преобразования — callback. Функция, переданная аргументом, всё равно является значением и копируется по обычным правилам. Когда значение — `nil`, его тип известен, но вызываемого кода нет. Публичный API, принимающий callback, должен решить, допустим ли `nil`, и либо проверить его, либо явно указать, что требуется ненулевая функция.

В литерале `func() { fmt.Println(name) }` идентификатор `name` связывается с переменной внешней области. Если затем присвоить `name = "новое"`, вызов замыкания увидит новое значение. В функции-фабрике такая связь позволяет хранить состояние между вызовами: каждый вызов фабрики создаёт свою переменную, а возвращённая функция меняет её. Если вернуть несколько функций, созданных вокруг одной переменной, они смогут совместно читать и менять это состояние.

Это не скрытая копия всей функции и не гарантия автоматической потокобезопасности. Замыкание захватывает переменные, которые использует его тело; если функция запускается в горутине, переменная может пережить возврат из внешней функции. Одновременное изменение захваченной переменной несколькими горутинами требует синхронизации так же, как поле структуры или глобальная переменная.

При сохранении callback из цикла учитывайте версию языка и то, объявляется ли переменная или переиспользуется. Для `:=` внутри цикла с языковой версией Go 1.22+ отдельное значение каждой итерации исключает классическую ловушку захвата. Присваивание существующей переменной всё ещё разделяет одно состояние. При сомнении сделайте зависимость видимой: передайте `value` аргументом функции или присвойте его локальной переменной с понятным именем перед созданием замыкания. Пример обеих форм приведён в разделе [«Управляющие конструкции и range»](./control-range.md).

На сервере замыкания полезны для связывания зависимости с обработчиком: например, `makeHandler(store)` возвращает функцию, которая обращается к конкретному хранилищу. Такой код проще тестировать, чем зависимость из глобальной переменной. Но замыкание, созданное однажды при запуске сервера и обслуживающее параллельные запросы, не должно без защиты мутировать общее захваченное состояние. Если состояние существенно для контракта, структура с методами часто делает его видимее при чтении, профилировании и ревью.

## Пример

```go
package main

import "fmt"

func counter(start int) func() int {
	n := start
	return func() int {
		n++
		return n
	}
}

func main() {
	first := counter(10)
	second := counter(100)
	fmt.Println(first(), first(), second(), first())
}
```

Результат `11 12 101 13` показывает, что каждый вызов фабрики создал независимую переменную `n`, а повторные вызовы одного и того же замыкания продолжают обновлять его состояние.

## Ошибки и ограничения

- Не полагайте, что замыкание захватило значение на момент объявления: оно может прочитать последующее изменение переменной.
- Не вызывайте функциональное поле, не определив контракт для `nil`.
- Не считайте замкнутое состояние потокобезопасным; разделяемые горутины требуют синхронизации.
- Не используйте замыкание для сокрытия важной зависимости, если явный параметр или поле структуры понятнее.
- Не запускайте сохранённые callback из цикла, пока не решили, нужен каждому callback свой элемент или общий счётчик.
- Не смешивайте «функция вернулась» с «захваченная переменная исчезла»: доступное замыкание сохраняет используемую переменную живой.

<summary>Почему два вызова counter(0) создают независимые счётчики?</summary>

Каждый вызов `counter` входит в отдельный вызов функции и создаёт отдельную переменную `n`; возвращённые функции сохраняют доступ каждая к своей переменной. Senior follow-up: что изменится, если фабрика вместо счётчика захватит общий указатель или общий объект?
