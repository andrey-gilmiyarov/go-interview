# Значения и указатели

## Коротко

В Go аргумент функции и присваиваемая переменная получают значение. Если это структура или массив, копируется их содержимое; если это указатель, копируется адрес. Поэтому копия указателя всё ещё ведёт к той же переменной. Это простая модель «значение переносится целиком», но она не означает, что каждая копия независима: значение может содержать указатель, срез, карту или интерфейс, которые продолжают ссылаться на общие данные.

Указатель типа `*T` хранит адрес переменной типа `T` либо `nil`. Оператор `&x` получает указатель на адресуемую переменную, а `*p` читает или меняет её значение. Выбирайте указатель, когда контракту нужна общая идентичность или изменение переданного объекта; не добавляйте его автоматически ради сокращения копирования маленькой структуры.

## Как работает

При `b := a` для структуры `Point` создаётся отдельная переменная `b` с копиями полей. После присваивания `b.X = 9` поле `a.X` не меняется. Если же `p := &a`, а затем `q := p`, копируются значения-адреса: выражения `*p` и `*q` обозначают одну переменную. Это похоже на две закладки на одной записи, а не на две записи.

Обычная передача аргумента устроена так же. Функция получает локальную копию аргумента и может изменить её поля, но изменение локальной структуры само по себе не меняет переменную вызывающего кода. Переданный `*Point` позволяет функции менять исходную структуру, потому что обе стороны располагают адресом одной переменной. Вместе с тем указатель не отменяет локальности других значений: присваивание нового адреса параметру внутри функции меняет только параметр.

Указатель может быть `nil`. Чтение или запись `*p` при `p == nil` вызывает panic, поэтому публичные функции, принимающие необязательный указатель, должны определить, означает ли `nil` пропуск, значение по умолчанию или ошибку. `new(T)` выделяет переменную нулевого значения типа `T` и возвращает `*T`; для структуры часто проще и яснее написать `&T{...}`. В обоих случаях не нужно вручную решать, будет ли объект размещён на стеке или в куче: размещение выбирает компилятор, а память, на которую остаются доступные указатели, отслеживает сборщик мусора.

Важная граница адресуемости: локальную переменную и поле адресуемой структуры можно взять через `&`, но значение `m[key]` у карты не является адресуемым. Для обновления элемента-структуры его читают в локальную переменную, меняют и записывают обратно; либо хранят в карте указатели, если общая идентичность действительно нужна. Для срезов копируется заголовок среза, а не весь массив; поэтому две копии заголовка могут менять общие элементы. Подробнее это разобрано в статье [«Срезы»](./slices.md).

Указатель не является механизмом синхронизации и не передаёт владение автоматически. Если одна горутина пишет в объект через указатель, а другая одновременно читает его без согласования, возникает гонка данных. Для backend-кода фиксируйте, кто может менять объект, и используйте каналы или синхронизацию, если состояние разделяется конкурентно. В `encoding/json` v1 ненулевой указатель кодируется как значение, на которое он указывает, а `nil`-указатель — как `null`; такое отображение является правилом сериализатора, а не особым свойством указателя.

## Пример

```go
package main

import "fmt"

type Point struct{ X, Y int }

func move(p *Point, dx int) {
	p.X += dx
}

func main() {
	a := Point{X: 2, Y: 5}
	b := a
	b.X = 9

	copyOfAddress := &a
	move(copyOfAddress, 3)
	fmt.Printf("a=%+v b=%+v same=%t\n", a, b, copyOfAddress == &a)
}
```

Код печатает `a={X:5 Y:5} b={X:9 Y:5} same=true`: копия структуры изменилась независимо, а функция через адрес обновила `a`.

## Ошибки и ограничения

- «В Go всё передаётся по ссылке» — неверно. Передаётся копия значения; иногда скопированное значение само содержит общий адрес или заголовок.
- Не принимайте указатель только из предположения, что копирование дорого. Сначала измерьте узкое место и оцените ясность API, `nil`-состояние и совместное изменение.
- Не возвращайте указатель лишь ради времени жизни. Возвращаемый объект остаётся доступен, пока на него есть ссылки; детали размещения — решение реализации.
- Не берите адрес элемента карты: компилятор запрещает `&m[key]`. Карта может перераспределить внутренние данные при росте.
- Общий указатель означает потенциально общий изменяемый объект. Это нужно учитывать в обработчиках запросов и фоновых задачах.

## Самопроверка

Разверните вопрос только после того, как сформулируете собственное объяснение.

<details>
<summary>После b := a для структуры, какие изменения b видны через a?</summary>

Поля структуры копируются, поэтому последующая запись в поле `b` не меняет `a`. Senior follow-up: перечислите случаи, когда поверхностная копия структуры всё же оставляет общие данные, например поле-указатель или срез.

</details>

<details>
<summary>Почему p := &amp;a; q := p; *q = 7 меняет a, а q = &amp;b не переназначает p?</summary>

`p` и `q` сначала содержат одинаковый адрес; разыменование любого из них обращается к одной переменной. `q = &b` меняет только локальное значение указателя `q`. Senior follow-up: как бы вы объяснили API, в котором параметр-указатель может быть `nil`, и где проверили бы это состояние?

</details>

<details>
<summary>Почему map[string]Point обычно требует чтения, изменения и обратной записи элемента?</summary>

Индекс карты не адресуем, а её внутреннее размещение может измениться при росте. Senior follow-up: когда карта указателей оправдана, а когда она лишь усложняет владение и синхронизацию?

</details>
