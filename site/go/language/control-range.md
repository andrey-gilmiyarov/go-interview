# Управляющие конструкции и range

## Коротко

`if`, `switch` и `for` выражают ветвление и повторение; в Go нет отдельной конструкции `while`, её роль выполняет `for condition`. `range` перебирает последовательности и возвращает значения согласно типу источника: индекс и элемент для массива/среза, смещение и руну для строки, ключ и значение для карты, полученные значения для канала. В Go 1.22 добавили перебор целых чисел, а в Go 1.23 — функций-итераторов.

Поведение захваченных переменных цикла зависит от формы объявления. В Go 1.22 и новее переменные, объявленные через `:=` в заголовке или `range`, отдельны для каждой итерации. Если цикл присваивает в уже существующую переменную через `=`, она одна и та же. Версия языка определяется директивой `go` в модуле, поэтому установленный новый компилятор сам по себе не меняет семантику старого модуля.

## Как работает

В трёхчастном `for` и в `range` важно различать создание переменной и присваивание существующей. `for i := 0; ...` объявляет `i`; при Go 1.22+ итерации получают отдельные переменные, что делает замыкания и отложенные callback безопаснее по отношению к позднему чтению индекса. `for i = 0; ...` присваивает в заранее объявленную `i`, поэтому функции, созданные в теле, ссылаются на одну переменную. Такая форма по-прежнему полезна, когда намеренно нужен общий изменяемый счётчик, но случайный захват часто становится ошибкой.

Та же граница есть у range: запись `for key, value := range records` объявляет переменные итерации, а `for key, value = range records` присваивает в уже существующие переменные. Последняя форма сохраняет один и тот же `value` для всех цикловых шагов; сохранённые замыкания видят его текущее, а не прежнее значение. Кроме того, переменная `value` для среза содержит копию элемента. Запись `value = updated` не меняет `records[index]`; меняйте сам срез по индексу или присвойте значение обратно. Это частая причина, по которой изменение «внутри range» выглядит успешным, но теряется после цикла.

Для среза `range` вычисляет границу по его длине при входе в цикл. Цикл выполнит количество итераций исходной длины: добавление элементов в теле не продлит обход. Однако значения элементов читаются при соответствующей итерации, а срез смотрит на базовый массив. Если код меняет ещё не прочитанный элемент через другой индекс, следующая итерация увидит новое значение. Если `append` перераспределил базовый массив, последующие записи в переменную среза могут уже не влиять на массив, по которому читает цикл. Для алгоритма с изменяемой длиной задавайте цикл явно и документируйте момент снимка.

Для карты порядок не гарантирован. Если ещё не достигнутая запись удалена во время обхода, она гарантированно не будет выдана; новая запись может быть выдана или пропущена. Для строки `range` декодирует UTF‑8 и возвращает байтовый offset, а не порядковый номер руны. Для канала цикл завершается после закрытия канала и опустошения буфера. Целочисленный `range n` даёт значения от нуля до `n-1`; диапазон не выполняет ни одной итерации при `n <= 0`.

Начиная с Go 1.23 `range` принимает функцию-итератор в одной из форм `func(yield func() bool)`, `func(yield func(V) bool)` или `func(yield func(K, V) bool)`. Переданные в `yield` значения становятся значениями итерации. Пока тело цикла продолжает обход, `yield` возвращает `true`; после `break` или другого завершения цикла он возвращает `false`. Итератор обязан остановиться и больше не вызывать `yield`. Так можно лениво выдавать записи и не вычислять остаток после ранней остановки. Это не заменяет `context.Context` для сетевой или блокирующей работы: такую отмену итератор должен учитывать отдельно.

Короткое объявление в инициализаторе `if`, например `if item, ok := cache[id]; ok { ... }`, вводит имена в область видимости всего `if` вместе с веткой `else`, но не после конструкции. Если снаружи уже есть `item`, объявление внутри `if` затеняет его; присваивание через `=` вместо этого использует существующую переменную. Проверяйте, какое имя затем читает код: изменение затенённого значения не меняет внешнее.

В `switch` выражение вычисляется один раз, а выполняется только первая подходящая ветка; после неё `switch` завершается автоматически. Переход в следующую ветку не происходит сам собой. В обычном expression switch явный `fallthrough` в конце ветки передаёт управление первому оператору следующей ветки, не проверяя её условие; он запрещён в последней ветке и в type switch. Это важно при чтении кода, где следующая ветка имеет условие, которое само по себе не совпадает.

Обычный `break` завершает ближайший охватывающий `for`, `switch` или `select`; обычный `continue` начинает следующую итерацию ближайшего `for`. Если нужно выйти из внешнего цикла из вложенного `switch` или продолжить внешний цикл, поставьте метку на нужный `for` и укажите её в `break` или `continue`. Условный `for` без условия продолжается, пока код не выполнит выход; серверный цикл должен учитывать контекст либо сигнал завершения.

В backend-обработке `range` часто используется для обработки пачки входных записей. Не удаляйте элементы среза по индексу в том же обходе без явной стратегии: сдвиг элементов меняет значения следующих индексов и легко пропускает работу. Постройте новый результат, проходите с конца или используйте отдельный индекс записи. При создании замыканий внутри цикла сначала определите, нужно ли каждой задаче собственное значение, а затем используйте объявление `:=` или передайте значение параметром callback явно. Это улучшает читаемость и позволяет тестировать порядок подготовки отдельно от планирования горутин.

Правила вставки и удаления карты во время range описаны выше; для snapshot сначала скопируйте ключи. Range по nil-срезу и nil-карте завершается сразу, но range по nil-каналу блокируется навсегда. Закрытый канал сначала отдаёт буферизованные значения и только затем завершает обход, что важно для потребителя, который ожидает его закрытия.

## Пример

```go
package main

import "fmt"

func main() {
	values := []int{1, 2, 3}
	seen := make([]int, 0, len(values))
	for _, value := range values {
		seen = append(seen, value)
		values = append(values, value*10)
	}
	fmt.Println("seen:", seen, "final:", values)

	var declared []func() int
	for i := 0; i < 3; i++ {
		declared = append(declared, func() int { return i })
	}
	var reusedIndex int
	var reused []func() int
	for reusedIndex = 0; reusedIndex < 3; reusedIndex++ {
		reused = append(reused, func() int { return reusedIndex })
	}
	for _, f := range declared {
		fmt.Print(f(), " ")
	}
	fmt.Println()
	for _, f := range reused {
		fmt.Print(f(), " ")
	}
	fmt.Println()
}
```

Срез `seen` остаётся `[1 2 3]`, хотя `values` в итоге содержит исходные и добавленные элементы: число итераций уже определено начальной длиной. При объявлении `i` замыкания вернут `0 1 2`; общий `reusedIndex` после цикла равен `3`, поэтому второй набор вернёт `3 3 3`.

## Ошибки и ограничения

- Не выводите порядок элементов карты из одного успешного запуска.
- Не ожидайте, что `append` внутри range-среза автоматически расширит число итераций.
- Не принимайте байтовый offset range по строке за порядковый номер руны.
- Не утверждайте, что все циклы на новом компиляторе используют семантику Go 1.22: проверьте директиву версии языка модуля.
- Не удаляйте из среза текущий элемент, не проверив последствия сдвига для следующего индекса.
- Не используйте присваивание в общую переменную цикла, если каждому сохранённому callback нужно собственное значение.
