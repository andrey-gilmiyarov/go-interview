# Карты

## Коротко

Карта `map[K]V` связывает уникальные ключи типа `K` со значениями типа `V`. Это изменяемая структура данных для поиска по ключу; её длина меняется по мере вставок и удалений. Нулевая карта равна `nil`: длину и чтение из неё использовать можно, но первая запись вызывает panic. Пустая готовая к записи карта создаётся через `make` или литерал.

Карта не задаёт порядок обхода, а выражение `m[key]` возвращает копию значения и не является адресуемой переменной. Эти два свойства важны для API и хранения состояния: порядок для вывода нужно задавать отдельно, а структуру-значение после изменения нужно записывать обратно.

## Как работает

Ключ карты должен поддерживать `==` и `!=`: поэтому срезы, карты и функции напрямую ключами быть не могут. Массивы, строки, числа, указатели и структуры из сравнимых полей подходят. Интерфейсный тип ключа компилируется, но конкретное динамическое значение тоже должно сравниваться: например, попытка положить срез в `map[any]V` приводит к panic во время выполнения. Это не следует путать с проверкой типа при компиляции.

Операция `value, ok := m[key]` различает отсутствие ключа и присутствующий ключ с нулевым значением. Простое `value := m[key]` в обоих случаях возвращает нулевое значение `V`, так что для счётчика или bool оно может скрыть отсутствие записи. `delete(m, key)` безопасен и для `nil`-карты; запись `m[key] = value` требует инициализированной карты. Размер можно задать как подсказку в `make`, но она не резервирует публично наблюдаемую ёмкость и не меняет контракт карты.

Язык не задаёт порядок элементов при `for key, value := range m`. Нельзя полагаться на одинаковую последовательность между запусками или на то, что вставленный во время обхода элемент обязательно будет посещён. Если ещё не достигнутый ключ удалён во время обхода, соответствующее значение не будет выдано; добавленный ключ может быть выдан или пропущен. Если API должен вернуть строки в стабильном порядке, соберите ключи, отсортируйте их и затем прочитайте значения. Это особенно полезно в логах, snapshot-ответах и тестах: сравнение сериализованного результата не должно зависеть от произвольной последовательности цикла.

Если `V` — структура, `m[key].Count++` не компилируется: результат индексирования не является адресуемым. Рабочий шаблон — `item := m[key]`, изменение `item`, затем `m[key] = item`. Альтернатива `map[K]*V` даёт общие изменяемые объекты, но добавляет состояния `nil`, вопросы владения и необходимость синхронизации. Выбирайте её из-за семантики, а не чтобы обойти одну строку записи.

Обычная карта не предназначена для одновременных операций записи и чтения/записи из разных горутин без синхронизации. Если несколько обработчиков меняют общее состояние, оберните карту в `sync.Mutex` или выберите модель с единственным владельцем данных. `sync.Map` существует, но подходит для специальных нагрузок и не заменяет автоматически карту с типизированным значением и понятным инвариантом.

Сериализатор `encoding/json` v1 отдельно задаёт формат: ключи объекта сортируются при кодировании, хотя обход карты в Go остаётся неупорядоченным. Не воспроизводите это поведение вручную в каждом цикле и не считайте сортировку свойством самой карты.

## Пример

```go
package main

import (
	"fmt"
	"sort"
)

func main() {
	scores := map[string]int{"anna": 2, "igor": 3}
	if score, ok := scores["mira"]; !ok {
		fmt.Println("mira отсутствует; нулевое значение было бы неоднозначно")
	} else {
		fmt.Println(score)
	}

	scores["anna"]++
	keys := make([]string, 0, len(scores))
	for name := range scores {
		keys = append(keys, name)
	}
	sort.Strings(keys)
	for _, name := range keys {
		fmt.Println(name, scores[name])
	}
}
```

Первый цикл извлекает только ключи, второй обходит их после сортировки. Чтение значения делается по актуальному ключу, а формат результата всегда воспроизводим.

## Ошибки и ограничения

- Не индексируйте без `ok`, если нулевое значение само по себе допустимо и нужно различить «не найдено».
- Не тестируйте функцию утверждением, что карта всегда обойдётся в конкретном порядке.
- Не считайте, что map-поле-структуру можно менять на месте; получите копию и присвойте её обратно.
- Не создавайте `map[any]...`, если ключи не ограничены сравнимыми динамическими значениями.
- Не разделяйте изменяемую карту между горутинами без явно выбранной синхронизации.
- Не выводите скорость или стратегию роста из `make(map[K]V, hint)`: точная реализация не входит в контракт приложения.
