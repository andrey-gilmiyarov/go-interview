## Коротко

Срез — небольшое значение, которое описывает видимый участок массива. Он хранит ссылку на начало этого участка, длину и емкость; сами элементы лежат в массиве. Поэтому присваивание среза копирует его описание, а не данные. Два среза могут обращаться к одним элементам и менять результаты друг друга.

Массив `[N]T` содержит фиксированное число элементов в типе и копируется целиком. Срез `[]T` — окно над массивом: заголовки могут иметь разную длину и делить хранилище. Поэтому присваивание среза не создаёт независимый снимок; контракт «только чтение» тоже не запрещает вызывающему коду менять элементы через другой алиас.

## Как работает

У среза есть два разных предела. `len(s)` показывает число доступных сейчас элементов. `cap(s)` показывает, сколько элементов можно охватить от первого элемента среза до конца массива без нового выделения памяти. Если `s := a[low:high]`, длина равна `high-low`, а емкость для обычного двухиндексного выражения зависит от конца исходного массива, а не от `high`.

Индексировать можно только элементы от нуля до `len(s)-1`; ёмкость не разрешает читать `s[len(s)]`. Она описывает запас, который операция `append` может использовать. Например, если `a` имеет длину шесть, а `b := a[2:4]`, у `b` видны два элемента, но ёмкость может включать ещё элементы до конца массива. Полное выражение `a[low:high:max]` задаёт границу ёмкости как `max-low`. Если установить `max == high`, добавление через этот под-срез уже не сможет перезаписать следующий элемент исходного массива и потребует отдельного массива. Уже видимые элементы при этом остаются общими.

Копирование среза не создает снимок массива: значения имеют свои поля длины и емкости, но указывают на один участок памяти. Это полезно для дешевой передачи последовательности, пока владение и границы изменения понятны.

`append(s, values...)` возвращает новое значение среза с обновленной длиной. Пока `len(s)+len(values) <= cap(s)`, операция повторно использует базовый массив. Когда места не хватает, будет выделено хранилище подходящего размера и существующие элементы скопируются. Спецификация гарантирует результат операции и использование массива при достаточной емкости, но не конкретное правило роста емкости, поэтому алгоритмы не должны зависеть от коэффициента вроде «всегда удваивается».

Передача среза в функцию копирует его заголовок. Функция может изменить элементы, потому что они лежат в общем массиве; но если она вызвала `append`, обновлённая длина находится только в её локальном заголовке, пока функция не вернёт результат. При достаточной ёмкости запись добавленного элемента всё ещё может попасть в общий массив за текущей длиной вызывающего кода. Поэтому контракт helper-функции обычно возвращает срез: `items = appendItem(items, next)`. Указатель на срез нужен редко; возвращаемое значение яснее показывает, что операция могла заменить заголовок и базовый массив.

Нулевой `nil`-срез — полноценный пустой вход: у него длина и ёмкость нулевые, его можно перебирать, передавать как пустой результат и пополнять `append`. Отличие от `make([]T, 0)` часто возникает на границе API, а не внутри алгоритма.

В `encoding/json` v1 нулевой срез превращается в `null`, инициализированный пустой — в `[]`; с тегом `omitempty` оба пустых варианта пропускаются. Выбирайте представление по контракту клиента, а не по случайному пути инициализации.

При разборе JSON v1 массив `[]` даёт новый пустой срез, а `null` присваивает `nil`; отсутствие поля оставляет уже заполненное значение без изменений. Поэтому PATCH-модель иногда должна отличать «поле не прислано», «очистить список» и «установить список». Тип `[]byte` кодируется v1 как строка Base64, а не как массив чисел.

`make([]T, n)` создаёт `n` доступных нулевых элементов; `make([]T, 0, n)` оставляет длину нулевой и задаёт запас. Выберите первую форму для заполнения по индексу, вторую — если будете добавлять через `append`. Длина наблюдаема вызывающим кодом, ёмкость служит запасом.

`copy(dst, src)` копирует столько значений, сколько помещается в меньший из двух срезов, и корректно обрабатывает перекрытие; это удобно для сдвига элементов при удалении. После сдвига вызывающий код сам уменьшает длину. `clear(s)` записывает нулевые значения до `len(s)`, но не меняет длину или емкость и не очищает весь резерв.

Срез можно сравнить с `nil`, но не с другим срезом. `slices.Equal` сравнивает элементы и считает nil- и пустой срез равными, хотя JSON v1 различает их.

## Пример

```go
package main

import (
	"fmt"
	"slices"
)

func main() {
	base := []string{"a", "b", "c", "d"}
	part := base[1:3]
	part[0] = "B"
	withAppend := append(part, "x")

	copyOfPart := slices.Clone(part)
	copyOfPart[1] = "C!"

	fmt.Printf("base=%v part=%v cap=%d\n", base, part, cap(part))
	fmt.Printf("append=%v clone=%v\n", withAppend, copyOfPart)
}
```

Вывод будет `base=[a B c x] part=[B c] cap=3`, затем `append=[B c x] clone=[B C!]`: `append` использовал массив и изменил `base[3]`, а `Clone` отделил последовательность. Копирование поверхностное: если элемент содержит указатель, объект остаётся общим.

Полное выражение среза меняет только емкость доступа для последующих операций:

```go
limited := base[1:3:3] // len=2, cap=2
detachedByAppend := append(limited, "y")
// добавление не перезаписывает base[3]
```

При этом `limited[0] = "X"` все еще изменил бы `base[1]`: для полной изоляции нужен клон.

## Ошибки и ограничения

- Изменение элемента видно через все срезы-алиасы; язык не предоставляет срез «только для чтения».
- Игнорирование результата `append` — ошибка логики. Содержимое массива иногда поменяется, а видимая длина переменной останется прежней.
- Маленький под-срез может удерживать в памяти большой массив. Если нужно сохранить только небольшой фрагмент надолго, скопируйте его в новый массив и освободите старую ссылку.
- При удалении ссылочных элементов очистите последний слот после сдвига, чтобы длинноживущий массив не удерживал удалённые объекты.
- `slices.Clone` сохраняет nil-состояние и копирует значения неглубоко, без клонирования вложенных объектов.

В backend-коде небольшой под-срез может удерживать в памяти весь большой буфер запроса. Если пул переиспользует этот массив после возврата, сохранённые байты позднее могут быть перезаписаны; скопируйте только нужный фрагмент, если он должен пережить запрос. Для синхронного прохода по большому входу копия заголовка среза позволяет читать без копирования элементов. В API-функции укажите, меняет ли она элементы, сохраняет ли алиас и кто владеет буфером.

<summary>Если b := a[2:4], какие элементы базового массива может изменить append(b, x)?</summary>

Если у `b` хватает емкости, `append` повторно использует массив и записывает следующий элемент после видимого участка `b`. Senior follow-up: как полное выражение `a[low:high:max]` ограничивает область записи для последующего `append`, и почему оно не изолирует уже видимые элементы?

</details>

<details>
<summary>Почему важно сохранить результат s = append(s, x), даже если массив мог измениться?</summary>

`append` возвращает значение с новым заголовком и длиной. При нехватке емкости результат указывает на новый массив, поэтому старый заголовок `s` не описывает добавленный элемент. Senior follow-up: какие инварианты нужно сохранить, если срез хранится в поле структуры и несколько методов могут его расширять?

</details>

<details>
<summary>Как encoding/json v1 различает nil-срез и make([]int, 0)?</summary>

У обоих длина нулевая, но `nil`-срез кодируется как `null`, а инициализированный пустой срез — как `[]`. Senior follow-up: какое представление должно использоваться в API-ответе, если клиент различает «значение неизвестно» и «пустой список»?

</details>
