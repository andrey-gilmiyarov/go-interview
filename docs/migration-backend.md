# Миграция backend-примеров

Старые backend-задачи перенесены в четыре самостоятельных упражнения и пакет <code>examples/backend</code>. Проверяемые примеры используют стандартную библиотеку; сетевые сценарии работают только с локальным <code>httptest</code>. В рамках всей согласованной миграции заменены 32 старых Go-файла и дополнительный extensionless Go source <code>test/middleware/main</code>. В backend-поддереве это семь файлов с расширением <code>.go</code> плюс указанный entry point.

| Старый источник | Проверяемая замена | Сохранённый сценарий и уточнение |
| --- | --- | --- |
| <code>test/new_logger/line_errors.go</code> | [line_validation.go](../examples/backend/line_validation.go) и [backend_test.go](../examples/backend/backend_test.go) | Unicode code-point length, отказ при длине не менее 20 и ровно два ASCII-пробела. Ошибка проверяется через errors.Is; несколько причин объединяются errors.Join. Старый MyCheck возвращал пустой LineErrors как ненулевой error interface, поэтому корректная строка ошибочно не была nil. Теперь успех возвращает настоящий nil. Старое условие !unicode.IsLetter считало ошибкой также пробелы и пунктуацию; исправленная проверка выявляет Unicode-цифры через unicode.IsDigit. |
| <code>test/new_logger/new_log_extended.go</code> | [logging.go](../examples/backend/logging.go) и [backend_test.go](../examples/backend/backend_test.go) | Сохранены три уровня Info, Warning, Error и фильтрация по порогу. Embedded Logger также продвигает Println, который обходит пользовательский фильтр; тест фиксирует этот эффект рядом с современным slog logger с Level. |

Потребителю отправки нужен только узкий MessageSender с одним методом. Тест использует реализацию только этого интерфейса; сетевые тела методов клиента намеренно опущены. |
| <code>test/user/user.go</code> и <code>test/user/user_test.go</code> | [user_handlers.go](../examples/backend/user_handlers.go) и [backend_test.go](../examples/backend/backend_test.go) | Запрос с пустым user_id отвечает 400, отсутствующий пользователь — 404, найденный — 200 с JSON. Тесты используют httptest recorder и проверяют также Content-Type. |
| <code>test/middleware/handler.go</code> | [user_handlers.go](../examples/backend/user_handlers.go) и [backend_test.go](../examples/backend/backend_test.go) | Сохранены поиск user_id в cookie и маршрут со списком URL. Отсутствующий cookie раньше печатал сообщение, после чего обращение к cookie.Value могло разыменовать nil. Новый handler возвращает JSON-пустой список. Middleware выставляет cookie до вызова handler; браузер отправит его только со следующим запросом, и тест проверяет обе стадии. |
| <code>test/middleware/main</code> | [user_handlers.go](../examples/backend/user_handlers.go) и [backend_test.go](../examples/backend/backend_test.go) | Исходный порядок AuthMiddleware перед GetUserURLsHandler сохранён в UserURLsRoute через EnsureUserCookie(handler) и проверен локальным запросом. Публичный listener на :8080 для учебного примера не нужен. |
| <code>test/resty/main.go</code> | [user_api_client.go](../examples/backend/user_api_client.go) и [backend_test.go](../examples/backend/backend_test.go) | Resty-вызов заменён на net/http client. Сохранены полный вложенный JSON пользователя и стабильная сортировка имён. httptest проверяет метод, путь, статус, декодирование тела, ошибочный HTTP status и malformed JSON без публичной сети. Response body закрывается при каждом результате. |

## Проверка удалённого extensionless source

Путь <code>test/middleware/main</code> был описан в brief как сгенерированный binary. Инспекция показала другое: <code>file</code> классифицировал его как C program text / ASCII text размером 176 bytes, а <code>od</code> показал текст <code>package middleware</code> и функцию <code>main</code> с Gin route composition. У файла не было executable mode, а расширение <code>.go</code> отсутствовало. Поэтому он удалён как устаревший extensionless Go entry point после переноса и тестирования порядка middleware; удаление не считается удалением исполняемого binary.

Пакеты старых каталогов удалены после прохождения тестов новых примеров. Gin, Resty и Testify не добавлялись. Путь для повторной проверки сценариев: <code>go test ./examples/backend</code>.
