# Kafka handbook и Go-лаборатория: 3.9 и 4.3.x

## Результат

Русский раздел `/kafka/` для Senior Go/backend: обзор, восемь глав и запускаемая лаборатория со сквозным сценарием заказа. Основная Kafka 4.3.1/KRaft, совместимость Kafka 3.9.2/ZooKeeper. Объяснить также поддержку KRaft в 3.9 и концептуальный путь миграции; не утверждать распространённость версий в enterprise.

Код только на franz-go. Только Confluent остаётся обзорным сравнением (librdkafka/CGO, API и эксплуатационные компромиссы), без установки второго клиента. Sarama, kafka-go, Watermill исключены. Все прежние материалы из закладок исключены как источники и содержательная база. Использовать заново проверенные первичные источники Kafka 3.9/4.3, franz-go выбранного тега, PostgreSQL; Debezium только для будущего CDC. Даты проверки не заменяют результаты запуска.

## Главы

1. Топики, партиции и журнал: ключи, offsets, retention/compaction, контракт JSON-события и порядок.
2. Репликация и запись: leader, ISR, acks, min ISR, ELR и отказ брокера.
3. Consumer groups: assignment, rebalance, classic/consumer protocols, жизненный цикл Go consumer.
4. Offsets и повторная доставка: обработка перед commit, падения, безопасная конкурентность между партициями.
5. Идемпотентность и транзакции Kafka: producer retries, consume-transform-produce, read_committed, ограничения внешних эффектов.
6. Дедупликация и внешние эффекты: атомарная запись event ID и бизнес-результата в PostgreSQL, конкурентные дубликаты.
7. Transactional outbox: атомарное изменение заказа и outbox, PostgreSQL + polling, повторы после публикации, порядок.
8. Обработка сбоев: retry/backoff, poison messages, DLQ/replay, backpressure, graceful shutdown, диагностика.

В каждой главе семь стандартных разделов handbook, минимум два скрытых ответа и практический разбор со скрытым решением. Реальный Go-код включать из файлов лаборатории, не дублировать в Markdown. Псевдокод допускается только с явной маркировкой. Общие гарантии объяснять один раз, различия 3.9/4.3 и клиента/protocol выделять явно. ZooKeeper/KRaft и сравнение franz-go/Confluent — в обзоре.

## Лаборатория

Отдельный модуль `labs/kafka`, не меняющий корневые Go-зависимости и упражнения. Go запускается с хоста, инфраструктура в Docker Compose. Закрепить franz-go v1.22.1 и pgx/v5 v5.11.0 и их транзитивные зависимости; применять Go toolchain репозитория. JSON: event_id, order_id (Kafka key), type, version и amount_cents. Уникальный event_id обозначает событие, а не попытку доставки.

Три отдельно запускаемые среды: один брокер 4.3.1/KRaft; один брокер 3.9.2/ZooKeeper; три брокера 4.3.1/KRaft для репликации и отказов. PostgreSQL доступен отдельно для outbox. Порты только loopback, учебные credentials, named volumes; обычная остановка сохраняет данные, reset удаляет только volumes выбранного учебного проекта отдельной явной командой. Закрепить patch-версии Docker-образов после проверки доступности на arm64/amd64.

Примеры: producer с подтверждением; последовательный consumer с ручным commit; ограниченная конкурентность между партициями с сохранением порядка внутри; транзакционная Kafka→Kafka обработка; создание заказа/outbox, polling publisher и идемпотентный consumer PostgreSQL. Для каждого — context, обработка ошибок, ограниченные ожидания, завершение. Не строить универсальный framework.

Сценарии автоматически проверяют бизнес-результат: повтор после обработки до commit, rebalance при втором consumer, успешная/отменённая транзакция, конкурентная дедупликация, повтор outbox после подтверждения Kafka до отметки публикации, отказ брокера при RF=3/minISR=2. Управляемые точки отказа и тайм-ауты вместо случайных sleep. Каждый запуск использует свои topics/groups/event IDs. Структурированные логи, команды диагностики; без Prometheus/Grafana.

## Debezium/CDC — следующий этап

В outbox-главе объяснить переход от polling к CDC и новые эксплуатационные обязанности. В roadmap зафиксировать отдельную будущую лабораторию Debezium + Kafka Connect с тем же заказом и сценариями отказов: logical decoding, replication slots/удержание WAL, snapshot, восстановление connector, повторная доставка, routing и наблюдаемость. Сейчас не запускать Debezium/Connect и не реализовывать CDC.

## Интеграция и выполнение

`site/data/kafka.json`: id, title, order, summary, kafkaVersion, comparisonVersion, reviewedAt, sources. Восемь Kafka-тем считаются отдельно от 42 Go-тем и 20 упражнений. Проверять структуру, уникальность, версии/даты, страницы, стандартные заголовки и локальные ссылки. Навигация Kafka, главная, каталог первичных источников и roadmap обновляются; существующий якорь roadmap сохраняется. Скрытые решения исключаются из поиска.

Работа в существующем worktree kafka-handbook. Lead владеет дизайном и приёмкой; Luna получает полные ограниченные контракты через agent_type=luna-worker, fork_turns=none. Разрешена параллельная работа по независимым файлам после фиксации интерфейсов; shared files строго распределены. Rework через ту же сессию. Задачи: реестр/тесты; Compose/скрипты; Go-код/тесты; главы/интеграция после готовности интерфейсов. Не коммитить и не менять staging.

## Приёмка

- Тесты реестра, маршрутов, обязательных разделов, ошибок ссылок и скрытого контента.
- npm run test:site; npm run docs:check; npm run docs:build; браузерная проверка навигации, поиска, details и мобильной ширины.
- В labs/kafka: go test ./...; go test -race ./...; go build ./...; отдельные integration-тесты на обеих версиях и отдельный отказ брокера.
- docker compose config для каждой среды; проверка готовности и фактических версий брокеров; инфраструктуру созданного запуска остановить без удаления данных после проверки.
- Корневые go test ./... и go build ./...; существующие ошибки вне scope не исправлять.
- git diff --check, git diff --cached --check, новые файлы, статус. В отчёте точные команды/результаты и ограничения; непроверенное не называть работающим.
